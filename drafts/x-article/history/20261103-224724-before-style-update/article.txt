One AI agent edited an LLM. A second built on its diff. DKG connected the work.

News classification rose from 38.7% to 80.0% on 1,000 held-out examples. A second local DKG participant reproduced it.

[IMAGE: assets/01-cover-x.png]What if one AI agent could improve an LLM, then hand the updated model and exact weight diff to another agent?


We now have a concrete, task-specific result in Neural Commons: a Codex-controlled agent edited 2,268 BF16 weights in an unmodified pretrained SmolLM2-135M-Instruct checkpoint. On a fixed 1,000-example AG News test subset, accuracy rose from 38.7% to 80.0%. A separate local participant reproduced the result through @origin_trail (https://x.com/origin_trail)’s Decentralized Knowledge Graph.


The inspiration was Rikiya Takehi’s post (https://x.com/rikiyatakehi/status/2117313742891327994) about Sparks of Weight-Space Programming (https://rikiyat.github.io/blog/weight-space-programming/). This project explores that agent-to-weights idea and the collaboration infrastructure around it. It does not claim to reproduce the paper’s Qwen results.


Code and evidence: github.com/lupuszr/neural-commons (https://github.com/lupuszr/neural-commons).


What the agent actually changed


The recorded controller used Codex with an existing login, requesting GPT-6 Astra. An OpenAI Responses API backend is also implemented; its live path has not been validated in this environment.


The host exposed tools to inspect weights, identify tokens, measure development examples and propose numerical edits. For this experiment, edits were restricted to the four task-label embedding rows: World, Sports, Business and Technology. These embeddings are tied to the model’s output weights.


The agent tested 13 proposals using 128 labeled development examples. It used supervised activation contrasts: differences between class means of the base model’s hidden states. The agent chose the coefficients and hypotheses; the host applied the recorded arithmetic. No gradients or optimizer were used. This still uses labeled data, and the contrast tool is an engineered affordance—not a claim that the agent invented the entire method unaided.


[IMAGE: assets/07-weight-agent-proposal.png]Actual Neural Commons proposal: a recorded agent decision becomes a reproducible weight patch.


A real held-out improvement


A separate 256-example validation split selected the candidate under a fixed rule. Then the checkpoint was frozen before the 1,000-example final test. The prompt, dataset split, original model and acceptance policy were fixed before the search.


The final result: 387/1,000 → 800/1,000 correct, a gain of 41.3 percentage points. Label negative log-likelihood fell from 1.797 to 0.548. The patch corrected 481 errors and introduced 68 new ones.


[IMAGE: assets/09-weight-results.png]Measured accuracy on the fixed 1,000-example AG News test subset. The agent did not receive these examples.


The acceptance contract also required preserving a previously exposed 56-example sentiment guard. Its accuracy and NLL stayed unchanged. A supplementary local check preserved the original scores on all 872 previously exposed SST-2 examples too. These checks constrain the claim; they do not establish that every capability was preserved.


[IMAGE: assets/06-weight-evaluation.png]The frozen candidate passed the news-improvement policy and the mandatory sentiment guard.


A second agent starts where the first stopped


We then gave GPT-6.1 Sol, also through Codex, the improved checkpoint and the first agent’s exact numerical diff: tensor names, indices, before/after values and deltas. It also received the earlier hypothesis, operations and aggregate results. The model and evidence came from a participant’s verified DKG artifact store.


Sol inspected changed values in all four label rows, tested 15 proposals on 256 fresh development examples, and a separate 512-example selection split chose the next patch. It changed 1,152 BF16 values relative to the inherited model, scaling the World row by 1.06 and Business by 1.03. No gradients or optimizer were used. These edits overlap the first patch; the counts are not additive unique weights.


On the same new 1,000-example final set: original model 39.8%; after Astra 84.2%; after Sol 84.5%. The incremental gain was 0.3 percentage points, with label NLL decreasing from 0.5214 to 0.4979. The sentiment guard remained unchanged. This is a different subset from the first-round 38.7% to 80.0% result.


[IMAGE: assets/10-continuation-results.png]The second agent continued from the first agent’s checkpoint. The current 0.2-point threshold was adopted after measurement; the original rejection is preserved.


The second step corrected 22 errors and introduced 19 new ones. It passes our current 0.2-point acceptance threshold. That threshold was lowered from 1 point after seeing the result; both the original rejection and the later policy reassessment remain public. The paired 95% interval for the accuracy change is approximately −0.96 to +1.56 points, so this small measured gain is not statistically conclusive.


The collaboration is the important new capability: a second controller can inspect the previous edit and continue from the exact resulting model. The child’s base checkpoint ID equals the parent’s candidate ID. DKG carries that ancestry and the evidence needed to verify each step. Both completed transport phases ran locally; an interrupted controller session and a failed reproduction attempt are also retained. The frozen second-stage scores and output hash were reproduced by another local participant. The revised acceptance decision was applied locally to those recorded measurements.


See the continuation results and exact diffs (https://github.com/lupuszr/neural-commons/blob/main/docs/CONTINUATION-RESULTS.md), replay workflow (https://github.com/lupuszr/neural-commons/blob/main/docs/CONTINUATION-WORKFLOW.md), and policy reassessment (https://github.com/lupuszr/neural-commons/blob/main/docs/continuation-policy-reassessment.json).


Why use OriginTrail DKG?


A screenshot of an improved score is a claim. Other participants need the exact model, patch, inputs, evaluator and policy to check it.


Neural Commons links ModelVersion, Hypothesis, PatchProposal, Evaluation, Review and DerivedVersion records in a DKG Context Graph. Content hashes bind the checkpoint, tokenizer, configuration, dataset, controller transcript and acceptance policy.


Propose: the agent freezes an edit; the generic Rust engine creates and reconstructs its patch.Share: DKG carries the linked experiment records and referenced artifacts to a participant starting with an empty artifact store.Reproduce: that participant verifies hashes, reconstructs the checkpoint and runs its locally configured evaluator.Return evidence: it publishes an evaluation and review through DKG; the first participant checks the author and proposal relationship.
In this run, both participants produced identical scores and the identical evaluator-output hash, including the regression guard. They used separate DKG identities, stores and evaluator processes on one physical machine.


[IMAGE: assets/08-weight-dkg-review.png]The second participant’s evaluation, retrieved through DKG. This LLM experiment used two local participants.


Weight files use native DKG artifact transport with hashed manifests and bounded blobs; individual weights are not RDF triples. DKG provides peer connectivity, Context Graph authorization and shared provenance. Neural Commons performs tensor edits and evaluation. DKG makes evidence available for checking; it does not make an improvement claim automatically true.


Failures and boundaries stay in the record


The first agent edit failed: it increased confidence without improving sentiment accuracy. A later SST-2 edit improved its target task but damaged the older sentiment probe. Both experiments remain documented. That regression motivated the mandatory guard in this news experiment.


The result is four-way forced-choice classification with one fixed plain-text prompt, on a length-filtered test subset. It is not an optimized chat-prompt baseline, a comparison against fine-tuning, or proof of better free-form generation. Public benchmark exposure during pretraining cannot be excluded.


The DKG run uses Shared Working Memory, a disposable local EVM and a documented local compatibility patch. It establishes local reproducibility, not public-chain finality or independent institutional validation. Earlier laptop/Mac mini transport tests are separate; this LLM result has not yet been reproduced across those two physical machines.


The next step is to extend this working two-controller chain with broader regression checks and independent participants deciding which improvements survive scrutiny. The named-tensor Rust engine remains architecture independent; task adapters are replaceable.

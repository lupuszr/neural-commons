# Neural Commons v1

V1 keeps the architecture-independent named-tensor engine and replaces the demo's peer HTTP artifact service with DKG-native artifact storage and transfer. The local content-addressed store is a verified working cache for tensor operations and evaluators. Graph Computer is not used.

## What changed

- File import, hashing, verification, patch application and export use bounded buffers. There is no 64 MiB ceiling on a checkpoint or payload. Safetensors headers and JSON metadata have separate budgets; tensor bytes stay on disk.
- Single Safetensors files and Hugging Face-style `*.safetensors.index.json` files are supported. Index shard paths must be simple local filenames; indexes, inventories and shard hashes are verified together.
- Region replacements support F32, F16 and BF16 without conversion. Nonfinite replacements, wrong parents, overlapping writes and invalid shapes/types/bounds are rejected. Untargeted bytes and original serialization headers are retained.
- `patch diff` generates bounded replacement payloads from two compatible checkpoint serializations. This version requires identical headers, tensor layout, shard assignment and inference artifacts. A serializer/layout change needs a format-normalization step; unsupported quantized edits fail explicitly.
- Artifact files are represented by signed DKG delivery records, a hashed file manifest and ordered native DKG blobs. Blobs adapt the current daemon's buffered upload endpoint; they do not limit the total checkpoint to one upload. Reads page through the native peer protocol with whole-artifact caching disabled. Both each blob and the reconstructed file are verified. Previously verified blobs remain available for a retry. Uncertain semantic writes remain `unknown` until readback confirms them; retry performs reconciliation without resending. Artifact preparation failures remain retryable before that write boundary.
- Participants need their own local DKG bearer token only. They do not exchange application artifact-service passwords. The DKG daemon handles peer connectivity and graph authorization. This client deliberately connects to its own loopback daemon; cross-machine traffic goes through DKG.
- Operator-configured evaluator processes are supported alongside the original CPU fixture. The CLI/UI can import checkpoints and inputs, create/apply patches, evaluate, propose/reproduce, fetch, export and select a version. Selection is an explicit local operator choice, not a consensus claim.

## Install and initialize

```sh
python3 scripts/setup.py --dkg-repo ~/projects/dkg-v9
cargo build --locked --workspace
```

Setup fetches the latest canary into an isolated checkout and applies [the narrow opaque-source read patch](../patches/dkg-opaque-source-read.patch). The original DKG checkout is not switched or reset. The patch permits reading the original source bytes of an upload whose extraction was intentionally skipped; it preserves `skipped` status and keeps failed/in-progress extraction rejected. Authorization checks remain in place. It is a local compatibility patch, not an upstream-merged change. Setup stops if it cannot apply cleanly to a new canary revision.

For a persistent participant, first configure its DKG daemon, identity, peer connection and authorized Context Graph using DKG. The local demonstration automates that setup on a disposable local EVM. Set an explicit persistent `store.options.path` when overriding the DKG store backend; selecting only a backend can create an in-memory store. Creating or registering public-chain graphs is not part of `nc init`.

```sh
target/debug/nc --home /path/to/alice init \
  --dkg-url http://127.0.0.1:9200 \
  --dkg-token-file /path/to/alice-dkg/agent.token \
  --context-graph OWNER_ADDRESS/GRAPH_NAME
```

Run the equivalent command with Bob's own daemon/token/home. Neither participant configuration contains the other's token. Initialize a new home when migrating from the original demo; historical evidence remains under its original runtime directory. `init` refuses to overwrite existing configuration.

## Work with your weights

```sh
nc --home ALICE register model.safetensors --inference-artifacts mapping.json
nc --home ALICE register updated.safetensors --inference-artifacts mapping.json
nc --home ALICE patch diff BASE_CHECKPOINT CANDIDATE_CHECKPOINT
nc --home ALICE patch apply BASE_CHECKPOINT PATCH
nc --home ALICE export CANDIDATE_CHECKPOINT /new/export/directory
nc --home ALICE publish-checkpoint CHECKPOINT
nc --home BOB fetch RECORD
nc --home BOB select CHECKPOINT
```

`nc` means `target/debug/nc`. The optional mapping JSON maps inference artifact names to local paths, e.g. `{"config":"/absolute/config.json","tokenizer":"/absolute/tokenizer.json"}`. Both versions must bind the same inference configuration for a weight-only comparison. For sharded checkpoints, pass the index JSON to `register`. `put FILE` imports arbitrary evaluation inputs or replacement payloads without loading the entire file into memory.

For external evaluators, `EvaluationSpec.config` is separately hash-bound task
configuration. It may differ from a checkpoint's inference artifact named `config`;
this lets an inherited checkpoint keep its identity across new tasks or rounds.
Base and candidate must still have exactly identical inference-artifact mappings.
The built-in MLP fixture retains its architecture-config identity requirement.

## Configure an evaluator

Each participant chooses trusted programs in `HOME/evaluators.json`. A proposal names an evaluator identity; it cannot choose a program or command line. Example:

```json
{
  "my-evaluator/v1": {
    "program": "/absolute/path/to/python3",
    "args": ["/absolute/path/to/adapter.py"],
    "identity_files": ["/absolute/path/to/adapter.py"],
    "backend": "my-runtime/v1",
    "max_timeout_ms": 60000,
    "max_output_bytes": 1048576
  }
}
```

`nc --home ALICE evaluators` reports the identities to put into an `EvaluationSpec`. The build digest covers the program, arguments, declared code/dependency identity files and backend. Paths of declared files can differ between participants because their bytes identify them. Operators must include all relevant code/dependency lockfiles and configure matching runtime environments. This is a trusted process boundary, not an OS sandbox; configure a sandboxed runner when evaluating untrusted model code. The application does not execute commands supplied by a proposal.

The program receives one additional argument: a temporary request JSON path. It contains `schema: nc/evaluator-request/v1`, `spec_id`, the exact `spec`, named `base_files` and `candidate_files` paths, and local dataset/config paths. It must emit a single JSON object on stdout:

```json
{
  "schema":"nc/evaluator-result/v1",
  "spec":"EXACT_SPEC_SHA256",
  "metric":"accuracy/v1",
  "base":0.0,
  "candidate":0.0,
  "backend":"my-runtime/v1"
}
```

The host verifies identities and finite scores and applies the policy itself. The external policy schema is `nc/metric-policy/v1` with `metric`, `direction` (`maximize` or `minimize`), `threshold`, `min_improvement` and `tolerance`. Infrastructure failures remain unavailable/interrupted rather than quality failures. The parent enforces a deadline on the worker process group; the configured runner also has runtime/output bounds. The execution lock is inherited by the runner so an orphan cannot overlap a retry.

For external adapters, `max_artifact_bytes` is a legacy fixture field and does not set a global artifact ceiling; use `0`. Adapter-specific input limits belong to the configured evaluator. The tiny built-in MLP retains its explicitly bounded in-memory input handling and is a regression fixture only.

## Reference real-data experiment

```sh
python3 scripts/iris_experiment.py --home ALICE --directory /new/iris-experiment
nc --home ALICE propose SPEC
nc --home BOB reproduce PROPOSAL_RECORD
```

Configure the same `nc/linear-classifier-python/v1` adapter on Bob (the full integration command below does this automatically). The script trains a single-layer softmax network with fixed epoch counts on a fixed training split, creates a diff, and evaluates on a separate held-out split. Training data and source attribution are bound as artifacts. The evaluation policy and training schedule are fixed before evaluation; no positive result is fabricated if the policy fails. This is a small reference experiment, not a large-model benchmark or novel capability claim.

Dataset: Fisher, R. (1936), [Iris, UCI Machine Learning Repository](https://archive.ics.uci.edu/dataset/53/iris), DOI `10.24432/C56C76`, CC BY 4.0. Downloaded bytes and the split seed are recorded in the experiment's `source.json`.

## UI

```sh
nc --home ALICE serve --port 19500
```

Open `http://127.0.0.1:19500`, enter the generated `ui.token`, and choose an operation. Input paths refer to files on the machine running the service. The UI is authenticated and loopback-only; it exposes saved evidence and a bounded set of operations. Its metadata endpoint serves local evidence for display; it is not used to transfer checkpoint bytes between peers. Tokens remain in memory in the browser, never in URLs.

## Validation

```sh
cargo test --locked --workspace
cargo clippy --locked --workspace --all-targets -- -D warnings
cargo fmt --all -- --check
cargo run --locked --bin nc -- demo
cargo build --locked --example large_checkpoint
/usr/bin/time -l target/debug/examples/large_checkpoint
node scripts/ui_check.cjs /path/to/completed-demo/a
```

`demo` is the automated local integration gate, including DKG transport, real-data evaluator reproduction and failure/recovery scenarios. It leaves logs/evidence and shuts down its child services. The browser check additionally needs Playwright Chromium, installed separately if absent. Exact results are in [V1-VALIDATION.md](V1-VALIDATION.md).

[Physical two-host validation](CROSS-HOST.md) passed between the laptop and Mac mini, covering controlled repair/regression, 96 MiB transfer and remote restart recovery. Public-chain finality, independently governed participants, production security/load qualification, quantized mutation and arbitrary model execution remain outside the demonstrated evidence.

## Scope and acceptance

1. Remove the application-wide 64 MiB artifact ceiling. Stream hashing/import/export, validate Safetensors headers without materializing tensor data, and apply/diff patches with bounded buffers. Support single and sharded checkpoints and byte-exact F32/F16/BF16 replacement. Reject invalid headers, regions, overlaps, nonfinite replacements, identity mismatches and unsafe shard paths. Demonstrate a checkpoint substantially larger than the processing buffer and record peak memory.
2. Reuse DKG Knowledge Asset file import, content identities, authenticated peer artifact reads and SWM sharing. The pinned DKG upload endpoint buffers a single upload, so represent large application artifacts as manifests of bounded DKG blobs. No custom cross-participant HTTP artifact server. Read pages without DKG's whole-artifact caching, verify blob and full-artifact hashes, retain resumable progress, and reconcile deterministic publications.
3. Provide persistent participant initialization/configuration and explicit graph connection workflows. Independent participant homes must have only their own DKG credentials. DKG is responsible for peer networking and authorization. Test actual signed DKG sharing and bytes crossing daemons, including unavailable, denied, interrupted and corrupt cases. Evidence from one host is not evidence from two physical hosts.
4. Provide an operator-configured evaluator process contract, executable identity and resource policy. Proposals cannot select arbitrary commands. Keep the CPU fixture as a regression test. Provide a useful reference adapter and reproducible evaluation inputs, and separate infrastructure failure from model-quality failure. Never promise an improvement before measuring it.
5. Expose import/diff/apply/propose/reproduce and evidence/version selection through usable CLI and UI workflows. Preserve durable job/publication history, add appropriate automated checks, and document setup and migration from the first delivery.

Limits apply to metadata, working buffers, runtime and operator-selected resource budgets, not a hardcoded maximum model file size. Unsupported quantized edits remain explicit. No automatic patch merging. End-to-end tests fetch latest origin/testnet-canary immediately before running and identify the tested revision. Any upstream gap or unavailable cross-machine validation must be reported separately from completed local checks.
